# 设计原则与已知限制

> [← 文档总览](index.md) · dynshot v0.0.1
---

## 一、通用设计原则（复用的价值所在）

1. **零网络依赖**：截图引擎本地打包 → 任何网站 CSP 都无法拦截
2. **元素级截图**：按 DOM 元素边界输出 → 无坐标/DPR/白边问题
3. **注入方式参考成熟开源**（Bilibili-Evolved）→ 经大量用户验证的对抗网站改版方案
4. **权限最小化**：无 background、无 debugger → 安装信任成本低
5. **适配器模式**：网站差异全部收敛为数据配置 → 核心一次写好，多站共用

---

## 二、已知限制

- 截图是**页面原样**（不改动内容）：相对时间（"x分钟前"）会保留
- 跨域图片需目标网站图床支持 CORS（SnapDOM 依赖 canvas 读取像素）
- `reconcile: true` 约双倍捕获时间
- 视频卡片截到的是暂停帧/封面
- 多图重排仅作用于适配器声明的横向滑动图集（如 B站 `.bili-dyn-gallery`）；重排网格图片为 `object-fit: cover` 方形缩略，与滑动画廊视觉不同
- opus 详情页依赖 `t.bilibili.com/{did}` 旧版动态页可用（ 跳转式截图的前提）；若 B 站下线旧版页，需回退到就地截图或自渲染方案
